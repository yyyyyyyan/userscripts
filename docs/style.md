# House style

This page sets the writing rules for everything in this repository that
people read: READMEs, changelogs, issue forms and script descriptions. The
base is the [Google developer documentation style guide](https://developers.google.com/style).
Where the two disagree, the rules below win.

1. Write for people who install scripts. Developer material goes in
   CONTRIBUTING.
2. The first sentence says what changes on the page.
3. Use "you", active voice and present tense. Put conditions before
   instructions.
4. Number steps, one action each. Put UI labels in **bold**, exactly as shown.
   Put code, keys and URL patterns in `code`.
5. Stay manager-neutral ("your userscript manager's menu"). Name a manager only
   for manager-specific behavior.
6. State what a script does *not* do, in a **Limitations** section.
7. Describe permissions in plain words.
8. Use sentence-case headings, no emoji in headings, and no badge walls. Images
   need alt text.
9. Write dates as YYYY-MM-DD and versions as `1.2.0`.
10. Terms: "userscript" (one word), "userscript manager", "Greasy Fork",
    "Violentmonkey", "Tampermonkey", "Greasemonkey". Write "select", not
    "click on".
11. `@description`: one sentence of about 120 characters or fewer, starting
    with a verb.
12. Changelog entries describe the user-visible effect, not the
    implementation.
